## 1. Latar Belakang & Prinsip Inti

Pesantren Modern Utsman Bin Affan membutuhkan tata kelola kehadiran yang terstruktur untuk seluruh Sumber Daya Manusia (SDM). Berbeda dengan absensi santri yang terikat pada kelompok/kelas/kamar santri, presensi SDM memiliki karakteristik khusus:

### Postulat Inti: `DAILY ≠ TEACHING ≠ TRAINING`
1. **Kehadiran Harian (Daily Check-in/Check-out)**:
   - Mencatat kehadiran fisik staff di lingkungan pesantren (gerbang utama / lobi kantor).
   - Menghitung ketepatan waktu berdasarkan jadwal jam kerja harian (`StaffWorkSchedule`).
   - **TIDAK OTOMATIS** menganggap guru hadir di dalam ruang kelas KBM atau pelatih di lapangan ekskul.

2. **Kehadiran Mengajar (Teaching Attendance)**:
   - Mencatat presensi riil guru di dalam kelas pembelajaran akademik (KBM).
   - Terikat langsung pada sesi akademik, jadwal mata pelajaran, dan kelas.
   - Mendukung pencatatan Guru Pengampu Terjadwal maupun Guru Pengganti Resmi (Inval).

3. **Kehadiran Melatih (Training Attendance)**:
   - Mencatat presensi pelatih/pembina pada sesi latihan ekstrakurikuler santri.
   - Terikat pada surat tugas atau penugasan pembina ekskul (`ExtracurricularStaffAssignment`).

## 2. Struktur Data & Entitas (Data Model)

### A. Entitas `Staff`
- `id`: Integer (Primary Key)
- `staff_number`: String (Unique NIP / ID Pegawai, contoh `STF260001`)
- `name`: String (Nama lengkap dan gelar)
- `gender`: `'male' | 'female'`
- `staff_type`: `'teacher' | 'trainer' | 'musyrif' | 'administration' | 'employee' | 'other'`
- `employment_status`: `'permanent' | 'contract' | 'honorary' | 'part_time' | 'volunteer' | 'inactive'`
- `qr_token`: String (Opaque token acak unik dengan prefix `STF-`, contoh `STF-K7P9NX26QM`)
- `rfid_uid`: String | null (UID kartu fisik terdaftar, dinormalisasi tanpa spasi/dash)
- `department`: String
- `position`: String
- `requires_daily_attendance`: Boolean (Default true)
- `is_active`: Boolean

### B. Entitas `StaffAttendanceRecord`
- `id`: Integer
- `staff_id`: Integer (Foreign Key ke Staff)
- `attendance_date`: String (`YYYY-MM-DD`)
- `attendance_type`: `'daily' | 'teaching' | 'training' | 'meeting' | 'duty' | 'event'`
- `context_type`: `'academic_session' | 'training_session' | 'duty_shift' | 'meeting' | 'general' | null`
- `context_id`: Integer | null
- `scheduled_start_at`: String (Timestamp ISO)
- `scheduled_end_at`: String (Timestamp ISO)
- `check_in_at`: String | null
- `check_out_at`: String | null
- `status`: `'present' | 'late' | 'permission' | 'sick' | 'leave' | 'official_duty' | 'absent'`
- `check_in_method`: `'qr' | 'rfid' | 'manual'`
- `check_out_method`: `'qr' | 'rfid' | 'manual' | null`
- `late_minutes`: Integer (Menit keterlambatan)
- `early_leave_minutes`: Integer (Menit kepulangan sebelum jam kerja selesai)
- `recorded_by`: String (Nama operator / ID perangkat)
- `notes`: String | null

### C. Entitas `StaffWorkSchedule`
- `day_of_week`: `'monday' | 'tuesday' | 'wednesday' | 'thursday' | 'friday' | 'saturday' | 'sunday'`
- `check_in_open_at`: String (`06:00`)
- `scheduled_start_at`: String (`07:00`)
- `late_after`: String (`07:15` — batas toleransi)
- `check_out_open_at`: String (`15:30`)
- `scheduled_end_at`: String (`16:00`)
- `is_working_day`: Boolean

## 3. Alur Operasional (Operational Workflow)

```
[Staff Tiba] ──► Scan QR / Tap RFID / Manual NIP
                      │
                      ▼
            [StaffIdentityResolver]
            - Validasi Aktif
            - Resolusi NIP / Token / UID
                      │
                      ▼
         [StaffWorkScheduleResolver]
         - Cek Hari Kerja
         - Cek Batas Toleransi Jam Masuk
                      │
                      ▼
         [StaffAttendanceService]
         - Belum Ada Record? ──► CHECK-IN (Hitung Late Minutes)
         - Sudah Check-in?   ──► CHECK-OUT (Hitung Early Leave Minutes)
         - Sesi KBM Mengajar? ──► TEACHING RECORD
         - Sesi Ekskul?      ──► TRAINING RECORD
                      │
                      ▼
            [AuditService Logging]
            - Log Event ke Audit Trail
```

---

## 4. Keamanan & Integritas Data

1. **Opaque QR Tokens**: Token QR SDM menggunakan string acak non-sekuensial (`STF-K7P9NX26QM`), mencegah tebakan/brute-force ID.
2. **RFID Normalization**: UID RFID distandarisasi huruf kapital tanpa delimiter untuk mencegah duplikasi entri kartu.
3. **Audit Trail**: Setiap perubahan status presensi (Koreksi, Tapping, Regenerasi QR, Asignasi RFID, Izin/Cuti) dicatat secara terperinci ke dalam log audit (`AuditService`).
4. **Auto-Alpha Finalization**: Fasilitas finalisasi harian otomatis mendeteksi staff wajib hadir yang tidak melakukan presensi dan tidak memiliki izin/cuti resmi, menetapkan status `absent` (Alpha) dengan catatan sistem.
